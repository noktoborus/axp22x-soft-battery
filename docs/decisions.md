# Decisions

Each entry: the number, the date, who decided, the decision. A proposal
not answered yet is in `plan.md`, "Open questions".

| # | date | by | decision |
|---|---|---|---|
| D1 | 2026-11-12 | user | A kernel module gives the battery of the system by itself. The scheme of now goes: `axp20x_battery` and the gauge of the AXP. |
| D2 | 2026-11-12 | user | The learning starts at the full charge, by a marker of the AXP. It ends when the AXP goes off: silent on I2C. |
| D3 | 2026-11-12 | user | At the end of the learning the module sends a uevent. udev starts a program of user space: it saves what was learned and runs `poweroff`. |
| D4 | 2026-11-12 | user | The patch 0010 of the kernel series (the watchdog of the silence of the AXP in `axp20x_battery`) goes. The module takes the silence of the AXP as the end of the learning. |
| D5 | 2026-11-12 | user | The node `battery-power-supply` of the AXP is turned off in the device tree (`status = "disabled"`). `mfd-core.c` then makes no device for it, and `axp20x_battery` does not probe. The module sets the PMIC up in its place: the current of the charge, `V_OFF`, the writes of Rex. Replaced by D36: the node is not touched; `axp20x_battery` is blacklisted. |
| D6 | 2026-11-12 | user | First step: the kernel module in a package (ebuild) of its own. |
| D7 | 2026-11-12 | user | A module shows the right level of the charge, by the learned model. |
| D8 | 2026-11-12 | user | The AXP is ignored as a store: it forgets what was written into its registers. No state of the module is kept in the AXP (not the buffer 0x04-0x0F, not E0:E1, not E2:E3). |
| D9 | 2026-11-12 | user | Replaced by D17. Was: a learning cut by `V_OFF` is closed by its last point saved on the disk. |
| D10 | 2026-11-12 | user | Assumed: `poweroff` on the CM5 cuts the power of the whole device. |
| D11 | 2026-11-12 | user | The module never powers the system off; only user space decides. |
| D12 | 2026-11-12 | user | No more logic and no workarounds in the kernel module. A guard against a failure of user space, when it is needed, is a separate module. |
| D13 | 2026-11-12 | user | The model reaches the module at boot by a rule of udev on the event `add` of its power supply; `ATTR{}` writes it into the attributes of the module. Not modprobe.d: it gives no options to a module built in. Changed by D30: the rule takes the model from the program (`IMPORT{program}`), not from a file (`IMPORT{file}`). |
| D14 | 2026-11-12 | user | The learning starts each time a charge ends in full; no start by hand. |
| D15 | 2026-11-12 | user | The module tells its events in dmesg: it is loaded, the model is awaited, the learning started, the learning done, and others (the list in `plan.md`). Taken as decided on 2026-11-12 with the list of `plan.md` after D33-D36 and its rule: a line at a change of state, not at each sample. |
| D16 | 2026-11-12 | user | While the learning runs, it is kept in the memory of the module only; the memory is to be small. At its end a uevent makes user space write the state file. |
| D17 | 2026-11-12 | user | A learning broken by a cut by `V_OFF` or a reboot is a failed learning and is dropped. The next full charge starts a new one. Replaces D9. |
| D18 | 2026-11-12 | user | upower stays. The module knows nothing of upower, nor when and by whom the system is powered off. When the module finds the AXP silent, a learning that runs ends; else the module does nothing more. |
| D19 | 2026-11-12 | user | At the silence of the AXP the module always sends a uevent. The program takes two events: the AXP silent (it forces a power off); the AXP silent with a model (it writes the state file, then forces a power off). The form, by D43: `health` = `Dead` in the uevent `change` of the class; the run is told by `learn_state` = `done`. |
| D20 | 2026-11-12 | user | The module makes the model of the curve, not user space: the program is not to run all the time or start often to write to the disk. |
| D21 | 2026-11-12 | user | With no model the end (0 %) is 3.2 V under load: the property `uconsole,end-microvolt = <3200000>` of the node of the module in its overlay; the default curve (the run of 2026-10-24, `hardware/notes/discharge-cm5.md`; the date was written 2026-11-08 by a mistake, fixed on the review) is cut there. With a model the end is its `V_end`, the last sample before the silence of the AXP, lower or higher than 3.2 V. Changed by D35: with a model the end is the highest `V_end` of the runs since `reset`, + 50 mV. With D36 the 3.2 V is a parameter of the module, `end_uv`. |
| D22 | 2026-11-12 | user | The model keeps a table under load, not a table of OCV: 21 points, one each 5 % of the charge out, each the mean V and the mean I as measured in the learning. A voltage of now is put on it by V_t(q) − (I − I_t(q)) × R. |
| D23 | 2026-11-12 | user | The level is C': the count, its speed scaled by the voltage. On a discharge the level falls at the speed of the count times f = (the level shown) / (left by the voltage), f in 0.5..2, and never rises (the formula fixed on 2026-11-12: it was written upside down; the aim, both at 0 % together, is the same); the voltage weighs nothing above 30 % and in full at 10 %; the means of V and I over 30 s. On the charger the count only; the end of the charge sets 100 %. The values are a first guess. |
| D24 | 2026-11-12 | user | One module: the set up, the count, the learning and the level in one driver; the code in files by part. The values of C' are parameters writable at run time. |
| D25 | 2026-11-12 | user | The program of user space is a package of its own, apart from the package of the module. It is written in Rust. |
| D26 | 2026-11-12 | user | The name is `uconsole-soft-battery`: the repository `uconsole-soft-battery`, the module `uconsole_soft_battery`, the power supply `uconsole-soft-battery`, the compatible `uconsole,soft-battery`, the overlay `uconsole-soft-battery.dtbo`, the package of the module `sys-power/uconsole-soft-battery`, the package of the program `sys-power/uconsole-soft-battery-tools`, the state `/var/lib/uconsole-soft-battery/`. With D36 there is no compatible and no overlay of our own: the module takes the compatible of the cell, `x-powers,axp221-battery-power-supply`. |
| D27 | 2026-11-12 | user | No service of systemd. The rule of udev of the silence runs the program right in `RUN`. The program writes its lines into `/dev/kmsg`. |
| D28 | 2026-11-12 | user | For now the ebuilds take the source as a copy in `files/` of each package. A script of this repository makes the copy and writes the sum of `files/` into the ebuild, as `kernel/bump.sh --sum`; this repository holds the true source. |
| D29 | 2026-11-12 | user | The program keeps the models it gets from the module, one per run, and the mean model it makes of them. The mean model is the one loaded at boot (D13). The module gives each run as it learned it, with no mix. When the mean is made: D30. |
| D30 | 2026-11-12 | user | The mean model is made when the model is loaded at boot, not when a run is saved. The set of runs may change between boots: runs may be deleted. (The mark of an unchanged source is dropped by D31.) |
| D31 | 2026-11-12 | user | No cache of the mean: at each load the program reads all runs there are and makes the mean again. No `model.env`. |
| D32 | 2026-11-12 | user | No package adds anything to `config.txt`. The package of the module tells by `elog` the line to add by hand: `dtoverlay=uconsole-soft-battery` in `[pi5]`, after `dtoverlay=clockworkpi-uconsole-cm5`. With D36 there is no overlay and no line to add; nothing goes into `config.txt` still. |
| D33 | 2026-11-12 | user | The module takes suspend into account. A suspend breaks the learning: it is dropped, as a failed learning (D17). |
| D34 | 2026-11-12 | user | R is a part of the model. The module learns it in each run from the step at its start (the charger out from the full state): R = (the voltage at rest − the mean voltage of the first 60 s under load) / (the mean current of those 60 s + the current at rest); no R (0) when the step is under 300 mA. The program takes the mean of R with the rest of the runs (D29). With no run, `uconsole,resistance-micro-ohms = <87000>` of the node of the module. With D36 the default R is a parameter of the module, `r_uohm`, not a property of a node. |
| D35 | 2026-11-12 | user | The end with a model: `V_thr` = the highest `V_end` (the mean voltage of the last 30 s before the silence) of all valid runs since the last `reset`, + 50 mV; not the mean of runs. The module steers the level by C' to the place of `V_thr` on the table moved to the current of now, and shows 0 % when the mean of 30 s of the voltage is `V_thr` or under. With no run, 3.2 V (D21). Changed by D48: the highest of the runs in `runs/` (the last 5), not of all since the last `reset`. |
| D36 | 2026-11-12 | user | The module binds to the cell `battery-power-supply` of the MFD `axp20x` in place of `axp20x_battery`. The package of the module installs `/etc/modprobe.d/uconsole-soft-battery.conf` with `blacklist axp20x_battery`. No overlay and no node of its own: the ADC by the IIO channels of `axp20x_adc`, 0x00 and 0x01 by the regmap of the parent, `battery@0` by `monitored-battery` of the cell. The kernel, its drivers and the device tree are not changed. |
| D37 | 2026-11-12 | user | The module weighs as little as it can on the running system: it takes as few locks as it can and uses the interfaces of the drivers there are. |
| D38 | 2026-11-12 | user | The module is small and easy to read. |
| D39 | 2026-11-12 | user | The full state: the charger in (from `axp20x-ac`, by `external_power_changed()`, the module named in `supplied_from`), the current of the charge by IIO under 100 mA, the voltage at least `voltage-max-design` − 50 mV. No read of 0x00 or 0x01. |
| D40 | 2026-11-12 | user | The full state is D39 and bit 6 of 0x01 = 0 (the AXP says no charge runs). The module reads 0x01, by the regmap of `axp20x`, only while the charger is in and the current of the charge is under 100 mA. `status`: no charger → `Discharging`; the charger in, the current 100 mA or more → `Charging` (no read); under 100 mA: bit 6 = 1 → `Charging`; bit 6 = 0 and the voltage at the threshold or over → `Full`; bit 6 = 0 under it → `Not charging`. `get_property` reads no register: it gives the last sample. |
| D41 | 2026-11-12 | user | The silence of the AXP: 6 failed samples in a row; a sample at most once a second. A sample is failed when all three reads of IIO in it (the voltage, the current of the charge, of the discharge) give `-ENXIO`; another error, or a part of the reads failed, is a line `ADC read failed` (rate limited), the sample is skipped and not counted. The number is a parameter, `silent_samples`. |
| D42 | 2026-11-12 | user | The work in time, as `plan.md`, "The work in time": one `delayed_work` on `system_power_efficient_wq`, `round_jiffies_relative(HZ)`, not deferrable, the time by `ktime_get()`; each run: the reads with no lock of ours, then under one mutex the count, the learning and the level, then out of it the notices; `power_supply_changed()` at a change of `status`, of the integer percent or of `capacity_level`; the charger by `external_power_changed()` and `power_supply_am_i_supplied()`; `get_property` and the attributes copy under the mutex, no read of the bus; one mutex of ours, nothing called under it. |
| D43 | 2026-11-12 | user | The interface, as `plan.md`, "The interface": the properties of the class, with `health` (`Dead` at the silence) and `internal_resistance` (R of the model in use); the attributes `model_*` (the draft, rw), `model_commit`, `model_source`, `run_*`, `learn_state`, `learn_charge`; the checks of `model_commit`; the silence told by `POWER_SUPPLY_HEALTH=Dead` in the uevent of the class, no uevent of our own; the keys `RUN_*`, `MODEL_*`; the parameters listed there. The bound of `V_end`: D51. |
| D44 | 2026-11-12 | user | The memory of the learning: the curve in 80 bins, the mean V (u16, mV) and I (u16, mA) each; the first step 25 mAh; when the 80 are full, each two next bins are merged into one and the step doubles. The table at the end is put on the bins by a line between their middles. The models (in use, the draft, the run) are kept in mV and mA (u16), the interface gives µV and µA. About 0.75 KiB in all, one allocation at the probe. The capacity is not guessed before the first full run: until then `charge_full` is `charge_full_design` of `battery@0`. |
| D45 | 2026-11-12 | user | The runs are kept in `/var/lib/uconsole-soft-battery/`: the valid ones in `runs/<seq>.env`, the ones that fail the check in `invalid/<seq>.env`. |
| D46 | 2026-11-12 | user | A third directory keeps the valid runs set aside: by a `reset`, or by age (more than the 5 of the mean in `runs/`). Its name and how D35 (the highest `V_end` since the last `reset`) reads it: `plan.md`, Q6. |
| D47 | 2026-11-12 | user | No mark of a reset: the runs set aside by age and by a `reset` both go into `archive/`, as they are. |
| D48 | 2026-11-12 | user | The highest `V_end` (D35) is taken of the runs in `runs/` only, the last 5. A `reset` clears it (3.2 V of D21 until the next run); a heavy run set aside by age no longer counts. Changes D35 ("since the last `reset`"). |
| D49 | 2026-11-12 | user | The forced power off is `systemctl poweroff --force`. |
| D50 | 2026-11-12 | user | The program may take the crates that fit; it is built with fat LTO (`[profile.release]`, `lto = "fat"`). Replaces "`std` only". |

| D52 | 2026-11-12 | user | `seq` of a run: at `save`, 1 + the highest number among the names in `runs/`, `archive/`, `invalid/`; six digits, `000001.env`; no file of a counter. |
| D53 | 2026-11-12 | user | `uconsole-soft-battery load --apply` writes the mean model into `model_*` of `/sys/class/power_supply/uconsole-soft-battery/`, then `1` into `model_commit`; with no valid run it writes `default` into `model_commit`, and the module takes its default model again. |
